# ChessWeb Analysis Methodology

ChessWeb uses client-side Stockfish 19 WASM to evaluate games locally in the browser. It provides an independent, transparent review pipeline inspired by public chess analysis conventions, with move classifications and accuracy calculations documented below.

## Engine Settings

- **Game Review**: Depth 16, MultiPV 2 (with adaptive single-PV fast-paths for terminal, forced, final, book, and losing top-move positions).
- **Parallel Worker Pool**: Up to 4 Stockfish WASM Web Workers run concurrently across CPU cores (`navigator.hardwareConcurrency`), each configured with a 64 MB Transposition Table (`Hash = 64`).
- **Reverse-Order Transposition Table Reuse**: Each worker evaluates its assigned contiguous game segment backward (`end -> start`) so that `fen[i + 1]` populates the worker's transposition table at full depth 16 immediately before `fen[i]` is searched.
- **Forced-Move & Terminal Fast-Path**: Positions with only 1 legal move derive their evaluation directly from the resulting position when available (or use `MultiPV = 1`), and terminal positions (`checkmate` / `stalemate` / `draw`) resolve immediately without an engine search.
- **Live Variation Exploration**: Depth 14, MultiPV 2.
- **Score Normalization**: Stockfish UCI reports centipawn and mate scores from the side-to-move's perspective. The worker client normalizes all stored evaluations to White's perspective (`+` favors White, `-` favors Black).

## Expected Score (Win Percentage)

Centipawn evaluations from the moving player's perspective are converted into expected score / win chances using the standard Lichess logistic curve:

```text
winPct(cp) = 50 + 50 * (2 / (1 + exp(-0.00368208 * cp)) - 1)
```

Mate scores map to `100%` for a forced mate in the player's favor and `0%` for a forced mate against the player.

For move classification, when the played move matches Stockfish's top choice from the pre-move search (or appears in the pre-move MultiPV lines with a higher evaluation than the post-move search), expected score is clamped so a top move is not penalized for one-ply search horizon drift.

## Move Classifications

Move labels are determined primarily from expected-score loss (`winPctLoss = max(0, winPctBefore - winPctAfter)`):

| Classification | Rule |
| --- | --- |
| **Book** | Resulting position matches the verified opening catalog within the first 24 plies (`winPctLoss < 2`, not walking into forced mate). |
| **Brilliant** | Top/near-top move (`winPctLoss < 2`) that sacrifices material (`SEE` or uncompensated drop >= 100cp), keeps `winPctAfter >= 50`, is not a promotion, and where the second-best move is < 95% win chance. |
| **Great** | Non-book, non-forced best move with `winPctAfter >= 50` where the second-best MultiPV line is at least 20 win-percentage points worse and below 70%. |
| **Best** | Top engine move or `winPctLoss <= 0` (also assigned to forced single-legal-move positions). |
| **Excellent** | `0 < winPctLoss <= 2` |
| **Good** | `2 < winPctLoss <= 5` |
| **Inaccuracy** | `5 < winPctLoss <= 10` |
| **Mistake** | `10 < winPctLoss <= 20` |
| **Blunder** | `winPctLoss > 20` |
| **Missed Win** | Decisive winning position (`winPctBefore >= 80`, or opponent just blundered leaving `winPctBefore >= 75`) drops to non-winning (`winPctAfter < 58`) with `winPctLoss >= 15`. |

## Accuracy Calculation

Move accuracy uses the Lichess per-move formula:

```text
moveAccuracy(winPctLoss) = clamp(0, 100, 103.1668 * exp(-0.04354 * winPctLoss) - 3.1669)
```

Game accuracy combines a volatility-weighted mean (using a sliding window standard deviation of White win chances, clamped to `[0.5, 12]`) with the harmonic mean of move accuracies for that color. Book moves are excluded unless all moves by that player were book moves.

## Opening Catalog

Opening names and ECO codes are matched by exact normalized board key (`piece placement + active color + castling rights + en-passant target`) generated by replaying legal SAN sequences through `chess.js`. If a move leaves known theory, the previous opening name is never backfilled onto later moves.
